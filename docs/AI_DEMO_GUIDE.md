# Local Testing & Recruiter Demo Guide: AI Fraud Detection

This guide walks you through bringing up the entire Global Wallet application locally and demonstrating the AI Fraud Detection to a recruiter.

We have already set `AI_FRAUD_ENFORCEMENT=true` in your `.env` file, which means the AI will actively block suspicious transactions.

---

## Step 1: Start the Entire Application

Open a new PowerShell window, navigate to your project root, and run the following commands sequentially to bring up the infrastructure and microservices.

### 1.1 Start Infrastructure
Start the database, message broker, and authentication service:
```powershell
docker-compose -f docker-compose.mongodb.yml up -d
docker-compose -f docker-compose.rabbitmq.yml up -d
docker-compose -f docker-compose.auth.yml up -d
```
*Wait about 10 seconds for Keycloak (auth) and MongoDB to fully initialize.*

### 1.2 Start Microservices
Start the API Gateway, Wallet Services, and Ledger Service:
```powershell
docker-compose up -d --build
```
*Wait 15 seconds for all services to connect.*

### 1.3 Verify Cluster Status
Check if the API Gateway is routing correctly:
```powershell
curl http://localhost:8080/api/v1/cluster/status
```
You should see `"wallet_service": "ok"` and `"ledger_service": "ok"`.

---

## Step 2: Get an Auth Token and Create Wallets

To make API calls, you need an access token from the Auth service.

### 2.1 Login as Admin
Run this to get your JWT token and store it in a variable:
```powershell
$response = Invoke-RestMethod `
    -Uri "http://localhost:8080/api/v1/auth/login" `
    -Method POST `
    -ContentType "application/json" `
    -Body '{"username":"admin","password":"change-me-in-production"}'

$TOKEN = $response.access_token
Write-Host "Token Acquired!"
```

### 2.2 Create Test Wallets
Create a source wallet (Alice) and a destination wallet (Bob):
```powershell
# Create Alice's Wallet (Funded)
Invoke-RestMethod -Uri "http://localhost:8080/api/v1/wallets" `
    -Method POST -Headers @{ Authorization = "Bearer $TOKEN" } `
    -ContentType "application/json" `
    -Body '{"wallet_id":"alice","currency":"USD","initial_balance":10000000}'

# Create Bob's Wallet (Empty)
Invoke-RestMethod -Uri "http://localhost:8080/api/v1/wallets" `
    -Method POST -Headers @{ Authorization = "Bearer $TOKEN" } `
    -ContentType "application/json" `
    -Body '{"wallet_id":"bob","currency":"USD","initial_balance":0}'
```

---

## Step 3: Test a Successful (Safe) Transaction

This transaction is a standard, low-value transfer. The AI will evaluate it, score it as low risk, and allow it to pass.

### 3.1 Execute the Safe Transfer
```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/v1/transfers" `
    -Method POST -Headers @{ Authorization = "Bearer $TOKEN" } `
    -ContentType "application/json" `
    -Body '{
        "source_wallet_id": "alice",
        "destination_wallet_id": "bob",
        "amount": 500,
        "currency": "USD",
        "idempotency_key": "safe-txn-001"
    }'
```

### 3.2 Verify the Result
- **Expected Output in Terminal:** You should receive a HTTP 200 `SUCCESS` response with a `transaction_id`.
- **Expected Verification (Logs):**
  Check the wallet service logs to see the AI decision in real-time:
  ```powershell
  docker logs wallet-service-primary --tail 20
  ```
  Look for a log line like:
  `[AI-FRAUD] src=alice dst=bob amount=500 USD score=0.10 decision=ALLOW`

## Step 4: Test a Fraudulent (Blocked) Transaction

Now we simulate a high-risk transfer. A very large amount being transferred to a completely new, unknown offshore wallet. The AI will detect this pattern.

### 4.1 Execute the Fraudulent Transfer
```powershell
try {
    Invoke-RestMethod -Uri "http://localhost:8080/api/v1/transfers" `
        -Method POST -Headers @{ Authorization = "Bearer $TOKEN" } `
        -ContentType "application/json" `
        -Body '{
            "source_wallet_id": "alice",
            "destination_wallet_id": "unknown-offshore-wallet",
            "amount": 5000000,
            "currency": "USD",
            "idempotency_key": "fraud-attempt-001"
        }'
} catch {
    $_.Exception.Response | Select-Object StatusCode
    $reader = New-Object System.IO.StreamReader($_.Exception.Response.GetResponseStream())
    $reader.ReadToEnd()
}
```

### 4.2 Verify the Result
- **Expected Output in Terminal:** The API Gateway will block the request and return an HTTP 403 (Forbidden) with an error message generated by the AI:
  ```json
  {"error": "blocked by fraud detection: High-value transfer to a previously unknown wallet"}
  ```
- **Expected Verification (Logs):**
  Check the logs again to see the AI intervention:
  ```powershell
  docker logs wallet-service-primary --tail 20
  ```
  Look for a log line like:
  `[AI-FRAUD] src=alice dst=unknown-offshore-wallet amount=5000000 USD score=0.92 decision=BLOCK`

## Recruiter Talking Points

When demonstrating this, emphasize these architectural points:

1. **"Fail-Open Design"**: Mention that the AI is an *additive layer*. If the Google API goes down, or the key is missing, the system gracefully defaults to `ALLOW`. It will *never* block legitimate business operations due to a vendor outage.
2. **"Event-Driven Observability"**: Highlight that the AI score isn't just printed to a log—it is pushed into the `MongoOutbox` via the `s.emit()` function, meaning it flows asynchronously to RabbitMQ for data warehousing and dashboarding without slowing down the HTTP request.
3. **"Dynamic Context"**: Explain that you pass a lightweight schema (`FraudSignals`) to the AI, ensuring low token usage (cost efficiency) while maintaining high accuracy for pattern detection (velocity, volume, unknown pairs).
